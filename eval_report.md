# Task 3: RAG Core Logic and Evaluation — Final Report

## 1. Pipeline Summary

| Component | Implementation |
|---|---|
| Vector store | Pre-built `complaint_embeddings.parquet` (1,375,327 chunks across the full filtered dataset), loaded into a FAISS `IndexFlatIP` index (cosine similarity via L2-normalized vectors) |
| Embedding model (query-time) | `sentence-transformers/all-MiniLM-L6-v2` — same model used to produce the corpus embeddings |
| Retrieval | Top-k similarity search, k=5, over the full FAISS index |
| Prompt template | Analyst-role framing, context-only instruction, explicit "don't have enough information" fallback (see `src/rag_pipeline.py::PROMPT_TEMPLATE`) |
| Generator (final) | `Qwen/Qwen2.5-0.5B-Instruct`, run locally via `transformers.AutoModelForCausalLM`, no API cost |
| Generator (rejected) | `google/flan-t5-base` — produced unusable output (single words, repeated phrases, leaked metadata tags) due to its 512-token context limit truncating retrieved chunks, and insufficient capacity to synthesize multi-paragraph complaint text |

Two earlier generator backends were tried and abandoned before settling on Qwen2.5-0.5B-Instruct: FLAN-T5-base failed for the technical reasons above, and the Anthropic Claude API was not usable due to lack of a USD payment method. Qwen2.5-0.5B-Instruct was chosen as a free, fully local, causal-LM alternative with a much larger context window (32K tokens vs. FLAN-T5's 512), which resolved the truncation problem entirely.

## 3. What Worked Well

- **Retrieval was reliable across every question tested.** All 16 inspected source excerpts (top-2 per question, 8 questions) were genuinely topically relevant to their question — the FAISS index built from the pre-supplied 1.37M-chunk embedding set is functioning correctly, and `all-MiniLM-L6-v2` is successfully matching question intent to relevant complaint language even on informal, lowercased, lightly-cleaned consumer text.
- **When source excerpts contained specific, quotable language** (explicit fraud descriptions, explicit legal non-compliance, explicit unauthorized-transaction statements), **generation was strong (score 4)** — the model directly incorporated source phrasing rather than inventing its own framing.
- **Switching generators fixed a categorical failure.** The earlier FLAN-T5-base backend produced literally unusable output (single words, repeated phrases, copied metadata tags) on every single question. Diagnosing this as a context-truncation and model-capacity problem, then switching to a causal LM with a much larger context window, fixed the failure mode entirely — every one of the 8 Qwen-generated answers was a coherent, multi-sentence, on-topic response.

## 4. What Could Be Improved

- **Hallucination risk rises sharply when retrieved excerpts are short, vague, or lack specific quotable detail.** The two worst-scoring answers (rows 3 and 7, scores 2 and 1) both occurred where the source excerpts were comparatively thin or abstract ("ten transactions, no extra charge"; "debt collection practices"). In both cases, the model filled the gap with invented specifics — a fee amount and multiplier in row 3, and an entire fabricated scenario (a named location, a dollar figure, a personal narrative) in row 7. This is a precise, actionable finding: **the prompt's "don't have enough information" instruction is not reliably triggered when context is merely thin rather than absent** — it only seems to engage when there are zero relevant results, not when results are present but underspecified.
- **The model sometimes over-elaborates beyond what 5 short chunks can support**, padding strong early points with generic, plausible-sounding industry commentary (row 1's later points on "regulatory compliance," "customer education") that isn't traceable to the specific excerpts shown.
- **Source attribution is occasionally unreliable** — row 8 shows the model misdescribing what a specific numbered excerpt actually says, which would mislead a reader who trusts the model's citation without checking the original source.
- **Model size is a real constraint.** Qwen2.5-0.5B-Instruct (500M parameters) was selected over the larger 1.5B variant specifically because of repeated multi-hour download stalls on a constrained connection, not because it was the better choice for accuracy. Future work should re-test with Qwen2.5-1.5B-Instruct (or a paid API-based model) under better network conditions, since the hallucination pattern observed here is a known weakness that tends to improve with model scale.
- **No test case for the "zero relevant results" fallback** was included in this 8-question set — all 8 questions had genuinely relevant complaints in the dataset. A future evaluation round should include at least one deliberately out-of-scope question (e.g., asking about a product not in the filtered dataset) to verify the "I don't have enough information" instruction actually engages correctly.

## 5. Recommendations for Task 4 (UI) and Beyond

1. **Surface the retrieved sources alongside every generated answer in the UI**, not just in this evaluation table — given the hallucination risk documented above, users should be able to check the model's claims against the actual excerpts it was given.
2. **Consider a stricter prompt addition** instructing the model to flag uncertainty per-claim (e.g., "only state a specific number, name, or location if it appears verbatim in the context above") to reduce the row 3/row 7-style fabrication.
3. **If budget allows**, re-run this same 8-question evaluation with a larger or API-based generator (Qwen2.5-1.5B-Instruct, or Claude) for a direct quality comparison against these Qwen2.5-0.5B-Instruct baseline scores
